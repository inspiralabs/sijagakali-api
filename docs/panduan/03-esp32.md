# 03 — Setup ESP32 (sensor level air)

ESP32-C5 membaca sensor ultrasonik A01ANY4B (Modbus RS485), menghitung level air, lalu
mengirimnya lewat WiFi router ke broker MQTT di VPS (`mqtts://mqtt.inspiralabs.id:8883`,
TLS). Firmware tidak pernah mengirim angka palsu: kalau sensor gagal baca, data berhenti
dan heartbeat membawa `last_error` (dipantau `field-health.sh` di VPS → Telegram topik SiJagaKali).

ESP32 **tidak** bergantung pada kamera atau Raspberry Pi — cukup WiFi router + internet.

> Terkait: Device ID harus sama di dashboard, firmware, dan akun MQTT; password MQTT
> dibuat di VPS — lihat [peta kredensial](README.md#peta-kredensial--nilai-yang-saling-terkait).

## Kebutuhan

| Barang | Catatan |
|---|---|
| ESP32-C5-DevKitC-1 | Board yang dipakai firmware |
| Sensor **A01ANY4B** varian **RS485 (Modbus RTU)** | Ultrasonik, dipasang di atas sungai menghadap ke bawah |
| Modul **TTL↔RS485 auto-direction** | Penghubung sensor ke ESP32 |
| Catu daya **5–12V** untuk sensor | Sensor punya catu sendiri, **bukan** dari pin 3.3V ESP32 |
| Adaptor USB 5V untuk ESP32 + kabel data USB | Untuk flash & daya |
| Box anti air | |
| Laptop dengan **VS Code + PlatformIO** (atau `pio` CLI) | Untuk flash pertama lewat USB |
| WiFi router TL-MR100 (2.4 GHz) | SSID + password |

### Wiring
```
Sensor A01ANY4B          Modul TTL↔RS485          ESP32-C5
 merah  → +5..12V         TXD → GPIO5 (RX)
 hitam  → GND             RXD → GPIO4 (TX)
 kuning → A+              VCC → 5V
 putih  → B-              GND → GND
GND sensor, GND modul, GND ESP32 harus tersambung (ground bersama).
```

## A. Siapkan akun & data (sekali per device)

1. **Device ID** — dashboard admin → Perangkat → **Tambah perangkat**, mis. `node-001`
   (sudah ada). Isi juga tinggi sensor, ambang waspada/siaga/bahaya, interval baca.
2. **Akun MQTT device** — di VPS (`ssh inspiralabs@72.62.125.210`):
   ```bash
   sudo /opt/server-setup/bin/mqtt-user.sh add node-001
   ```
   Password acak **dicetak sekali** — simpan di password manager.
   `node-001` **sudah dibuat**; passwordnya:
   ```bash
   sudo -u deploy cat /srv/apps/sijagakali-api/.mqtt-node-001.pass
   ```
   Username akun **harus sama** dengan Device ID (broker membatasi device hanya ke
   topik `sijagakali/<device_id>/...`). Jangan pakai akun `sijagakali-backend` di ESP32.

## B. Isi konfigurasi firmware (di laptop, JANGAN di-commit)

Repo `sijagakali-firmware`, file `src/main.cpp`:
```cpp
#define WIFI_SSID "nama-wifi-TL-MR100"
#define WIFI_PASSWORD "password-wifi"
#define MQTT_BROKER_URI "mqtts://mqtt.inspiralabs.id:8883"   // sudah benar
#define MQTT_USER "node-001"                                // = Device ID
#define MQTT_PASSWORD "password-dari-langkah-A2"
#define DEPLOYMENT_SLUG "sijagakali-bojong-kulur"
#define DEVICE_ID "node-001"                                // = Device ID
#define SENSOR_HEIGHT_CM_DEFAULT 600.0   // jarak sensor ke dasar sungai kering (cm), node-001 = 600
#define READ_INTERVAL_SEC_DEFAULT 3600   // jeda MAKSIMAL antar kiriman; diubah dari dashboard
#define SENSOR_POLL_SEC 30               // sensor dibaca tiap 30 detik
#define SEND_DELTA_CM 10.0f              // perubahan >= 10 cm langsung dikirim
#define FIRMWARE_VERSION "sijagakali-v1.2.0"   // naikkan tiap rilis (dipakai OTA)
```
Pastikan memakai branch firmware **tanpa data dummy** (`master` setelah PR #2 di-merge,
atau `fix/sensor-no-dummy`).

## C. Flash pertama lewat USB
```bash
cd sijagakali-firmware
pio run -t upload -t monitor
```
(Windows: `~/.platformio/penv/Scripts/pio.exe run -t upload -t monitor`)

Di Serial Monitor harus muncul berurutan:
```
WiFi connected, IP=192.168.1.x
MQTT: connected
Distance = ... cm
Published sensor/data: {...} [ok]
Published sensor/status heartbeat
```
Lalu di dashboard device tampil **online** dan grafik level air bergerak.

| Masalah di Serial | Penyebab umum |
|---|---|
| WiFi tidak connect | SSID/password salah; router harus 2.4 GHz |
| WiFi OK, MQTT tidak connect | Password MQTT ≠ akun di VPS; `MQTT_USER` ≠ nama akun; kuota/internet router habis |
| `Sensor gagal ... sensor_no_reply` | Wiring A+/B- tertukar, TXD/RXD tertukar, sensor tanpa catu 5–12V |
| `Sensor gagal ... sensor_no_echo` | Sensor membalas 0 = pantulan tidak kembali: pelampung hilang/macet, sensor miring, target > 7,5 m. Data tidak dikirim, error tampil di `last_error` heartbeat |
| `Zona buta sensor` | Ada benda/air < 28 cm dari sensor — level dilaporkan maksimum (alarm) |
| `Sensor gagal saat air dekat sensor -> anggap zona buta` | Bacaan terakhir ≤ 80 cm dari sensor lalu sensor gagal/membalas 0 — kemungkinan sensor tertutup/terendam air. Level maksimum tetap dikirim (alarm jalan), `last_error` berakhiran `-> blind_zone` agar operator tahu level ini dugaan. Cek CCTV |

## D. Kalibrasi tinggi sensor (di lokasi)
Ukur level air sebenarnya (mis. 35 cm dari dasar) lalu kirim perintah dari VPS:
```bash
sudo docker compose -f /opt/server-setup/infra/docker-compose.yml exec mosquitto \
  mosquitto_pub -u sijagakali-backend -P 'PW_BACKEND' -t sijagakali/node-001/command \
  -m '{"cmd":"calibrate","request_id":"cal-1","params":{"reference_water_level_cm":35}}'
```
Firmware menyimpan tinggi sensor baru ke flash (bertahan setelah restart). Samakan juga
"Tinggi sensor" device di dashboard dengan nilai yang dilaporkan (`sensor_height_cm=...`
di ack / Serial Monitor).

**Level air dihitung di firmware** (`level = tinggi sensor − jarak`); "Tinggi sensor" di
dashboard hanya catatan, tidak dipakai menghitung. **Status** (normal/waspada/siaga/bahaya)
ditentukan di server (data-processing) dari ambang di dashboard — ubah ambang tanpa flash.
Tinggi sensor tersimpan di flash menimpa `SENSOR_HEIGHT_CM_DEFAULT`; untuk kembali ke nilai
di kode: `pio run -t erase` sebelum upload, atau kirim `calibrate`.
Pastikan ambang bahaya < tinggi sensor − 28 cm (zona buta), agar status bahaya bisa tercapai.

## E. Update berikutnya lewat OTA (tanpa kabel)
1. Naikkan `FIRMWARE_VERSION`, `pio run` → file `.pio/build/esp32-c5-devkitc-1/firmware.bin`.
2. https://ota-sijagakali.inspiralabs.id (login admin dashboard) → **Firmware** →
   unggah; kolom **Versi** harus sama persis dengan `FIRMWARE_VERSION`.
3. **Perangkat** → **Deploy** ke device (harus **online**) → pantau di **Riwayat**.
   Gagal = device tetap memakai firmware lama.

## Interval & heartbeat
Sejak `v1.2.0` membaca sensor dan mengirim data dipisah:
- Sensor **dibaca tiap 30 detik** (`SENSOR_POLL_SEC`), hasilnya hanya dikirim ke server bila:
  - level berubah ≥ 10 cm dari kiriman terakhir (naik atau turun, `SEND_DELTA_CM`),
  - masuk/keluar zona buta,
  - sudah lewat **Interval Pengiriman Data** (dashboard) sejak kiriman terakhir,
  - pembacaan pertama setelah boot, atau perintah `sample_now`.
- Jadi interval di dashboard = jeda **maksimal** antar data. Contoh 1 jam: kondisi tenang
  → 1 data/jam (DB & WA hemat); air naik → data langsung masuk dalam ±30 detik.
- Kiriman gagal (MQTT putus / jam belum sinkron) dicoba lagi di pembacaan berikutnya.
- Interval baru dari dashboard berlaku dalam ±30 detik, tidak menunggu jeda lama habis.
- `SEND_DELTA_CM` disetel di lokasi: bila pembacaan sering naik-turun sendiri, naikkan.
- Interval dikirim dengan MQTT **retain**, jadi ESP32 yang baru tersambung/reboot langsung menerima nilai terakhir.
  Interval tersimpan di flash menimpa `READ_INTERVAL_SEC_DEFAULT` — simpan ulang dari dashboard setelah flash.
- Heartbeat tiap 120 detik. Data/heartbeat berhenti → laporan di Telegram topik SiJagaKali
  (`field-health.sh` di VPS, tiap 5 menit). Peringatan sensor lewat WA sudah dihapus — WA hanya untuk warga.
